# Changelog

Все заметные изменения проекта «Time Capsule 2.0» документируются в этом файле.

## [1.0.0] - 2026-11-10 (Official Release)

### Релизная подготовка и исправления
- **Релизные артефакты Android:**
  - Настроены `versionCode = 1` и `versionName = "1.0.0"`.
  - Включена оптимизация R8 (`minifyEnabled = true`, `shrinkResources = true`), размер APK оптимизирован до **4.4 МБ**.
  - Создан полный набор правил `proguard-rules.pro` для kotlinx.serialization, Ktor Client, OkHttp, Credential Manager, googleid, DataStore, Coil и Compose.
  - Настроена подпись релизной сборки через `keystore.properties` и создан скрипт генерации ключей `./make-keystore.sh` (RSA 2048, 10 000 дней). Сгенерирован подписанный `app-release.apk` и `app-release.aab`.
  - Добавлены адаптивные векторные иконки приложения в теме Tokyo Night (`ic_launcher`, `ic_launcher_round`, `ic_launcher_monochrome` для Android 13+ themed icons) и Splash Screen API.
  - В `AndroidManifest.xml` выставлено `allowBackup = "false"`, добавлены разрешения `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`, `INTERNET`, `POST_NOTIFICATIONS`.
- **Автономный сервер (Fat JAR):**
  - Создана задача `fatJar` в `backend/build.gradle.kts`. Сервер компилируется в автономный исполняемый `timecapsule-server.jar` (~25 МБ) и стартует за 0.9 секунды без Gradle.
  - Созданы скрипты `./start-server.sh` (с проверкой занятости порта 8080) и `./reset-data.sh` (безопасный сброс базы с подтверждением).
  - Добавлены `Dockerfile` и `docker-compose.yml` с монтированием тома `./data`.
  - Fail-fast: при `DEMO_MODE=false` без `CAPSULE_AES_KEY` сервер немедленно завершает работу с понятным описанием ошибки; при `DEMO_MODE=true` использует демо-ключ с логированием предупреждения.
  - Внедрён in-memory `AuthRateLimiter` для защиты `/api/v1/auth/*` от брутфорса (максимум 20 попыток в минуту).
  - Добавлена периодическая фоновая очистка просроченных сессий раз в 60 секунд и удаление просроченных токенов при попытке доступа.
- **Исправления стабильности клиента:**
  - Google Credential Manager: реализован двухэтапный поиск аккаунта (сначала `setFilterByAuthorizedAccounts(true)`, при `NoCredentialException` повтор с `false`).
  - Предотвращение повторных кликов: добавлен guard `isSubmitting` при отправке формы создания капсулы.
  - Сетевая безопасность: настроен `network_security_config.xml` с явным разрешением cleartext только для доверенных локальных адресов (`10.0.2.2`, `localhost`, LAN IP) с документацией по переходу на HTTPS для публичного релиза.

## [2.2.0] - 2026-11-10

### Добавлено
- **Личные капсулы и новая серверная логика (P1):**
  - Поддержка личных капсул без гео-привязки (`isGeoLocked = false`): капсула принадлежит только создателю и открывается строго по наступлению даты (`now >= unlockDate`), без необходимости проверки расстояния и присутствия других участников.
  - Расширение модели капсулы полями: `kind` (по умолчанию `MESSAGE`, зарезервированы `PHOTO` и `VOICE`), `recipient` (адресат, до 255 символов), `tags` (до 5 тегов без знака `#`, длина каждого до 30 символов), `isGeoLocked` (по умолчанию `true` для совместимости с ранее созданными капсулами).
  - Персональные статусы участия в капсуле: `openedAt: Long?` (время фактического открытия) и `archived: Boolean` (флаг архивации капсулы текущим пользователем).
  - Вычисляемый статус капсулы для текущего пользователя `status`: `SEALED` (запечатана, время ещё не наступило), `READY` (готова к открытию), `OPENED` (открыта пользователем), `ARCHIVED` (в архиве).
  - Новые API эндпоинты:
    - `POST /api/v1/capsules/{id}/open` — фиксирует факт открытия капсулы (`openedAt = now`). Если условия открытия ещё не выполнены, возвращает `409 Conflict`.
    - `POST /api/v1/capsules/{id}/archive` — перемещает капсулу в личный архив пользователя (`archived = true`).
    - `POST /api/v1/capsules/{id}/unarchive` — извлекает капсулу из личного архива (`archived = false`).
    - `DELETE /api/v1/me/data` — полностью удаляет все данные текущего пользователя (созданные капсулы, участие в чужих капсулах, активные сессии).
  - Принцип «Если закрыто, то закрыто»: капсула неизменяема после создания, а секретный текст закрытых этапов никогда не передаётся клиенту до наступления момента открытия (заменяется на заглушку `[ЗАШИФРОВАНО AES-256-GCM]`).
  - Серверная валидация: дата открытия в будущем (минимум +1 минута в обычном режиме, смягчена для `DEMO_MODE=true`), заголовок до 255 символов, секретный текст до 5000 символов, до 5 тегов.

- **Обновлённая навигация и новые экраны Android (Tokyo Night):**
  - Нижняя панель навигации из 5 разделов: «Главная», «Капсулы», «Создать», «Идеи», «Настройки». Существующие экраны «Радар» и «Таймлайн» сохранены и доступны по бесшовным переходам.
  - **«Главная» (`HomeScreen`):** приветствие с никнеймом, крупная карточка быстрого создания «Запечатать новое воспоминание», карточка «Ближайшее открытие» с живым таймером обратного отсчёта (дни, часы, минуты, секунды), быстрое присоединение по коду и быстрый переход в радар.
  - **«Капсулы» («Полка воспоминаний», `CapsulesShelfScreen`):** клиентский поиск по названию, адресату, типу и тегам; 4 вкладки статуса («Запечатанные», «Готовые», «Открытые», «Архив»); жесты Pull-to-refresh; карточки с бейджами типа, адресата и тегов; кнопка «Открыть» для готовых капсул; меню действий архивации/разархивации.
  - **«Создать» (`CreateCapsuleScreen`):** пошаговый мастер создания — Шаг 1 (выбор типа: Текст, Фото со статусом «Скоро», Аудио со статусом «Скоро»), Шаг 2 (заголовок, послание до 5000 символов, адресат, теги через пробел/запятую), Шаг 3 (чипы сроков: «Завтра», «Через неделю», «Через месяц», «Выбрать дату» через DatePicker, в демо-режиме доступен чип «[ДЕМО] через 1 минуту»), сводная карточка предпросмотра, блок предупреждения о невозможности редактирования запечатанного текста, диалог подтверждения перед отправкой; переключатель «Открыть только на месте (гео + друзья)» для гео-капсул с радаром и выбором участников.
  - **«Идеи» («Искра для истории», `IdeasScreen`):** вдохновляющий каталог готовых шаблонов (Письмо себе через 10 лет, Прогнозы на 2036 год, Послание будущему ребёнку на 18-летие, Годовщина, День рождения, Семейная история) с переносом текста и настроек в форму создания в один клик.
  - **«Настройки» (`SettingsScreen`):** отображение профиля (имя, email, аватар) и кнопка выхода; адрес сервера и переключатель Demo Mode; защита приложения 4-значным PIN-кодом (криптографическое хэширование salt + SHA-256 в DataStore Preferences, диалог ввода PIN при старте, аварийный сброс через выход); экспорт данных в JSON (`Intent.ACTION_SEND` с защитой: секретный текст экспортируется только для уже открытых капсул); удаление всех данных с подтверждением (`DELETE /api/v1/me/data`); диалоговые окна «О приложении», «Политика конфиденциальности», «Условия использования»; тумблер локальных уведомлений.

- **Синхронизация контрактов и тестирование:**
  - `ModelsDto.kt` 100% идентичен между `backend` и `android-client`.
  - Успешный прогон unit-тестов бэкенда (`./gradlew test build`) и проверок Android-клиента (`./gradlew assembleDebug lint`).
  - Сквозные автоматизированные тесты жизненного цикла капсулы (создание, запечатывание, 409 при раннем открытии, переход в `READY`, открытие через `POST /open`, архивация, разархивация, `DELETE /me/data`).

## [2.1.1] - 2026-11-10

### Исправлено и улучшено
- **Изоляция и видимость данных:**
  - `GET /api/v1/capsules` возвращает только капсулы, где пользователь является создателем или участником.
  - `GET /api/v1/capsules/{id}`, `check-in` и `demo-force-checkin` для чужих капсул отвечают `404 Not Found` (исключена утечка факта существования капсул).
  - Поле `inviteCode` скрывается (`null`) для неавторизованных к капсуле пользователей.
  - Эндпоинт `/api/v1/capsules/join` очищает пробелы (`trim()`), нечувствителен к регистру и идемпотентен (повторное присоединение возвращает капсулу без ошибок и дублирования записей).
- **Миграция схемы БД:**
  - Безопасная инициализация базы с помощью `SchemaUtils.createMissingTablesAndColumns`.
  - Автоматическая миграция унаследованных баз данных с генерацией 6-символьных инвайт-кодов для капсул без кода.
- **Тесты:**
  - Добавлены юнит-тесты на проверку изоляции видимости, сценарии `/capsules/join` и миграцию схемы БД со старой структурой таблиц.

## [2.1.0] - 2026-11-10

### Добавлено
- **Постоянное хранилище бэкенда (H2 в файловом режиме):**
  - Подключение к БД переведено на `jdbc:h2:file:./data/timecapsule;DB_CLOSE_DELAY=-1` с автоматическим созданием директории `./data`.
  - Капсулы времени, пользователи, этапы и сессионные токены сохраняются между перезапусками сервера.
  - Демо-данные (`seedDemoData()`) засеваются только если база данных пуста (0 пользователей и 0 капсул).
  - Файлы базы данных (`data/`, `*.mv.db`) добавлены в `.gitignore`.
- **Вкладка «Мои капсулы» в Android-клиенте:**
  - Отдельный экран со списком капсул времени, где текущий пользователь является создателем или участником.
  - Автоматическая гео-сортировка капсул по удалённости от текущих GPS-координат пользователя.
  - Интеграция `PullToRefreshBox` (Pull-to-refresh) для мгновенного обновления списка свайпом вниз.
  - Стилизованные пустое состояние (с кнопкой создания первой капсулы) и состояние ошибки сети (с кнопкой повтора).
  - Информативные карточки: роли «Создатель» / «Участник», дистанция, статус разблокировки, прогресс этапов и список участников.
- **Приглашение друзей и 6-символьные коды приглашения:**
  - Генерация уникального 6-значного кода приглашения (`inviteCode`) для каждой создаваемой капсулы (с исключением неоднозначных символов `0`, `O`, `1`, `I`).
  - Новый эндпоинт `POST /api/v1/capsules/join` для присоединения друга к капсуле по коду (с автоматическим переводом капсулы в статус групповой `isGroupCapsule = true`).
  - В `CreateCapsuleScreen`: динамический поиск участников по имени из `GET /api/v1/users`, горизонтальная лента выбранных участников в виде `InputChip` с бейджем «Создатель» и возможностью удаления.
  - В карточке капсулы: чип с кодом приглашения и кнопкой копирования в буфер обмена в один клик.
  - Диалог «Присоединиться по коду» (`JoinCapsuleDialog`) на экране «Мои капсулы».
- **Эффекты открытия капсулы и подсветка этапов:**
  - Тактильный отклик (`LocalHapticFeedback` с типом `LongPress`) при переходе статуса капсулы `isFullyUnlocked` из `false` в `true`.
  - Эффект неонового всплеска (анимированный радиальный градиент поверх 3D-модели капсулы и всплывающий неоновый бейдж «✦ КАПСУЛА РАЗБЛОКИРОВАНА ✦» с динамической толщиной рамки карточки).
  - Уведомление в Snackbar о разблокировке капсулы («✦ Капсула «...» разблокирована! Все участники рядом.»).
  - В экране таймлайна (`CapsuleStagesTimeline`): интеллектуальная подсветка текущего этапа (бейджик «ТЕКУЩИЙ ЭТАП», неоновая окантовка карточки цветом `TokyoAccent`, акцентный пульсирующий узел на вертикальной шкале времени).
