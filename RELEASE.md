# Релизная документация «Time Capsule 2.0» (Release 1.0.0)

Полное руководство по сборке, подписи, развёртыванию и проведению демонстрации на защите проекта.

---

## 1. Готовые артефакты релиза

Все релизные артефакты собраны с оптимизацией R8 (minification, resource shrinking) и подписаны релизным ключом:

| Артефакт | Путь к файлу | Размер | Описание |
|---|---|---|---|
| **Release APK** | `android-client/app/build/outputs/apk/release/app-release.apk` | **~4.4 МБ** | Подписанный релизный пакет для прямой установки на Android-устройства (`adb install`). |
| **Release AAB** | `android-client/app/build/outputs/bundle/release/app-release.aab` | **~8.3 МБ** | Android App Bundle для публикации в Google Play Console. |
| **Standalone Server JAR** | `backend/build/libs/timecapsule-server.jar` | **~25 МБ** | Автономный Fat JAR сервер со встроенным Netty, Exposed, H2 и всеми зависимостями. Стартует за 0.9 сек без Gradle. |

## 2. Сборка и подпись с нуля

### 2.1. Генерация ключа подписи (Keystore)
Для генерации ключа подписи используйте интерактивный скрипт:
```bash
./make-keystore.sh
```
Скрипт запросит пароль и сгенерирует 2048-битный RSA-ключ (`release.keystore`) со сроком действия 10 000 дней и создаст файл `keystore.properties` (оба файла добавлены в `.gitignore`).

Пример содержимого `keystore.properties`:
```properties
storeFile=release.keystore
storePassword=ВашПароль
keyAlias=timecapsule
keyPassword=ВашПароль
```
*(Если `keystore.properties` отсутствует, Gradle соберёт release-сборку неподписанной с предупреждением в консоли).*

### 2.2. Сборка Android-клиента
```bash
cd android-client
./gradlew lint assembleRelease bundleRelease testReleaseUnitTest --no-daemon
```

### 2.3. Сборка автономного сервера
```bash
cd backend
./gradlew test fatJar --no-daemon
```

## 3. Регистрация Release SHA-1 в Google Cloud Console

Для работы входа через Google в релизной сборке необходимо зарегистрировать релизный SHA-1 отпечаток:

1. Получите SHA-1 отпечаток вашего релизного ключа:
   ```bash
   keytool -list -v -keystore release.keystore -alias timecapsule
   ```
   *Текущий сгенерированный релизный отпечаток:*
   `SHA1: E3:58:E2:04:2F:A0:AC:BA:25:3D:3A:A5:EE:5A:B9:B5:1F:7F:CB:CA`

2. Перейдите в [Google Cloud Console](https://console.cloud.google.com/) $\rightarrow$ **APIs & Services** $\rightarrow$ **Credentials**.
3. Нажмите **Create Credentials** $\rightarrow$ **OAuth client ID**:
   - **Application type**: `Android`
   - **Name**: `Time Capsule 2.0 (Release)`
   - **Package name**: `com.example.cyberpunk` (строго без изменений!)
   - **SHA-1 certificate fingerprint**: вставьте полученный SHA-1.
4. Нажмите **Create**.
5. Убедитесь, что Web Client ID (`GOOGLE_WEB_CLIENT_ID`) указан в `local.properties` (для клиента) и в переменной окружения сервера.

## 4. Запуск и управление сервером

### 4.1. Быстрый запуск сервера
```bash
./start-server.sh
```
- Скрипт проверяет порт 8080. Если порт занят, выводит понятное сообщение об ошибке.
- Поддерживает переопределение порта: `PORT=8081 ./start-server.sh`.
- Работает напрямую через `java -jar backend/build/libs/timecapsule-server.jar`.

### 4.2. Сброс базы данных
```bash
./reset-data.sh
```
Останавливает процесс сервера на порту 8080, удаляет директорию `./data` и сбрасывает базу к чистому состоянию. При следующем старте сервер заново инициализирует схему и засеет демо-данные.

### 4.3. Запуск через Docker
```bash
docker compose up -d --build
```
База данных сохраняется в томе `./data`.

## 5. Сценарий показа на защите проекта (Step-by-Step)

Сценарий рассчитан на демонстрацию как на одном устройстве/эмуляторе, так и на двух реальных телефонах.

### Подготовка перед защитой:
1. Запустите сервер:
   ```bash
   ./start-server.sh
   ```
2. Установите релизный APK на телефон(ы) или эмулятор:
   ```bash
   adb install -r android-client/app/build/outputs/apk/release/app-release.apk
   ```

### Шаг 1. Авторизация (Демо-вход и Google-вход)
- **Телефон 1 (Мага):** Откройте приложение, нажмите кнопку **«Демо-вход: Maga (user_maga)»**. Вход происходит мгновенно даже без подключения к интернету/Google-сервисам.
- **Телефон 2 (Зайнаб):** Нажмите **«Демо-вход: Zainab (user_zainab)»** (или войдите через Google, если настроен интернет).
- *Что показать комиссии:* Тема Tokyo Night, неоновое лого, информативный экран входа, возможность работать офлайн в демо-режиме.

### Шаг 2. Главная и «Полка воспоминаний»
- Откройте вкладку **«Капсулы»**: отображается групповая капсула «Капсула Худжанд» со статусом `SEALED` (или `READY`).
- Продемонстрируйте фильтрацию: поиск по названию, 4 вкладки («Запечатанные», «Готовые», «Открытые», «Архив»), Pull-to-refresh свайпом вниз.
- На карточке капсулы виден 6-символьный код приглашения и кнопка копирования в буфер в один клик.

### Шаг 3. Создание личной капсулы «через 1 минуту»
- Нажмите вкладку **«Создать»**:
  1. Тип капсулы: оставьте «Сообщение» (покажите неактивные чипы «Фото» и «Голос» с бейджем «Скоро»).
  2. Заполните: Название («Послание на защиту 2026»), адресат («Для приёмной комиссии»), теги (`защита, проект, 2026`), текст послания.
  3. Срок: нажмите специальный чип **«[ДЕМО] через 1 минуту»**.
  4. Обратите внимание на карточку-итог и предупреждение «Если закрыто, то закрыто».
  5. Нажмите **«Запечатать капсулу»** и подтвердите в диалоге.
- Капсула создана в статусе `SEALED`. Текст этапа скрыт под меткой `[ЗАШИФРОВАНО AES-256-GCM]`. Попытка открыть её до срока блокируется сервером (HTTP 409 Conflict).

### Шаг 4. Сценарий на двух телефонах (Код приглашения + Радар)
1. На телефоне 1 скопируйте код приглашения из созданной капсулы.
2. На телефоне 2 введите этот код через кнопку **«Присоединиться по коду»** на Главной. Капсула мгновенно появляется на втором устройстве.
3. Откройте **«Радар»**: неоновая 3D-модель капсулы плавно вращается. При нажатии «Демо-чекин» участники виртуально собираются вместе, капсула разблокируется с виброоткликом и неоновым всплеском.

### Шаг 5. Открытие по таймеру и расшифровка
- Спустя 1 минуту статус капсулы переходит в **«Готово к открытию» (`READY`)**.
- Нажмите кнопку **«Открыть»**: сервер фиксирует `openedAt`, капсула переходит в `OPENED`, и текст расшифровывается в реальном времени с помощью AES-256-GCM.
- Откройте **«Таймлайн»**: покажите подсветку текущего этапа и дату открытия.

### Шаг 6. Настройки, безопасность и удаление данных
- Перейдите в **«Настройки»**:
  1. Покажите установку 4-значного PIN-кода (хэширование `salt + SHA-256` в DataStore).
  2. Экспорт данных в JSON через системное меню «Поделиться» (покажите, что закрытые капсулы не раскрывают текст, а открытые экспортируются).
  3. Нажмите **«Удалить все данные»**: вызов `DELETE /api/v1/me/data` полностью удаляет данные пользователя и сбрасывает сессию.

## 6. Список известных ограничений

1. **Типы медиа PHOTO и VOICE:** Поля зарезервированы в DTO и схеме базы данных; в интерфейсе создания они помечены бейджем «Скоро» и станут доступны в обновлении 2.0 с облачным S3-хранилищем.
2. **GPS в закрытых помещениях:** В учебных аудиториях и цокольных этажах точность GPS может снижаться, поэтому для защиты предусмотрен переключатель «Демо-чекин» (`demo-force-checkin`), гарантирующий 100% стабильную демонстрацию.
3. **Cleartext HTTP в локальной сети:** По умолчанию приложение разрешает локальный HTTP-трафик для отладки и подключения к локальному серверу по Wi-Fi. Для публичного размещения в магазинах приложений сервер должен быть закрыт SSL-сертификатом (HTTPS).
